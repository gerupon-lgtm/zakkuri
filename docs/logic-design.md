# 処理設計（計算・判定）

このアプリの中心となる計算を定める。L-03・L-07・L-08 はサクズと共通の部品（サクズの `src/shared/`。扱いは C-05b）で実装し、ここに書いた仕様と検証ケースは、共通部品のテストにも入れる。それ以外の計算は `src/core/` に、DOMに触れない純粋な関数として置き、`tests/` で検証する。

端数の丸めは、共通モジュールの `util/round.js`（`roundHalfUp`）を使う。

## 座標の約束ごと

- **元画像座標**: 読み込んだ画像（PDFは画像に変換した後）のピクセル座標。x は右向き、y は下向き。頂点・基準・四隅は、すべてこの座標で保存する。
- **補正後座標**: 台形補正をした後の画像のピクセル座標。補正しない場合は元画像座標と同じになる。長さや面積は、すべてこの座標で測る。
- **実座標（m）**: 補正後座標に縮尺を掛けた値。x_m = sx·x、y_m = sy·y。共通縮尺のときは sx = sy = s。
- **測量座標（SIMA・DXF用、後の版）**: X＝北、Y＝東。F-004で指定した北の向きに合わせて、実座標を回転して作る。

### L-01 PDFを画像に変換する

- **入力**: PDFファイル、ページ番号（1から始まる）。
- **処理**: PDF.js で、指定したページを 300dpi 相当（`scale = 300/72`）で画像にする【想定】。
  - 長辺が 8000px を超える場合は、8000px に収まるまで縮小する（メモリ対策）【想定】。
  - ページが1枚だけのときは、ページ選択を省略する。
- **エラー**:
  - `PDF_ENCRYPTED`: パスワードのかかったPDF。読み込めない旨を表示する。
  - `PDF_INVALID`: 壊れたPDF。読み込めない旨を表示する。
- **検証**: 2ページのPDFで、2ページ目を選んで変換できること。暗号化されたPDFで `PDF_ENCRYPTED` になること。

### L-02 台形補正（射影変換）

- **入力**:
  - 元画像座標の四隅。順番は 左上 → 右上 → 右下 → 左下。
  - 用紙の種類: A4 / A3 / B4 / 不明。向きは 縦 / 横。
- **出力**: 3×3 の変換行列 H（元画像座標 → 補正後座標）と、補正後の画像の幅・高さ。
- **補正後の縦横比**:
  - 用紙の種類が分かっている場合は、用紙の縦横比を使う（例: A4横は 297:210）。
  - 「不明」の場合は、四隅から測った「向かい合う辺の長さの平均」の比を使う。
  - 縦横比の小さな誤りは、L-04 の縦横別の縮尺で吸収される。
- **補正後の大きさ**: 長辺 4000px【想定】。
- **計算**: 4組の点の対応から、8元の連立方程式をガウスの消去法（部分ピボット選択つき）で解く。補正後の画像は、逆変換と双線形補間で作る。処理が重い場合は Worker に分けてよい（A区分）。
- **エラー**:
  - `QUAD_DEGENERATE`: 四隅のうち3点が一直線上にある、または四角形が自分自身と交差している。
- **検証**:
  - 長方形を射影変換した画像の四隅から H を求めると、元の長方形に誤差 0.5px 以内で戻ること。
  - 四隅を直した後も、頂点が元画像座標で保たれ、補正後座標が新しい H で計算し直されること。
- **用紙と縮尺表示**: 用紙の種類が分かっている場合だけ、「補正後の1px が用紙上で何mmか」（mm/px）を求め、公図の推定縮尺 1/N を表示する。用紙が不明で補正もしない場合、1/N は「—」と表示する。

### L-03 多角形の検証と面積

- **入力**: 頂点の列（補正後座標、または実座標）。
- **検証**:
  - 頂点が3つ未満のとき: `POLY_TOO_FEW`
  - 辺どうしが交差しているとき（隣り合う辺は除く）: `POLY_SELF_INTERSECT`
  - 面積が0のとき（すべての頂点が一直線上）: `POLY_ZERO_AREA`
- **面積**: 座標法（靴ひも公式）で求める。向きは反時計回りにそろえる。
- **検証**: 凸の四角形、L字形、星形（自己交差あり）、一直線上の3点を使ったテスト。

### L-04 縮尺の推定

記号:
- 辺の基準 i について、lᵢ = 補正後座標での2点間の長さ（px）、Lᵢ = 実際の長さ（m）
- a = 補正後座標での多角形の面積（px²）
- A = 公簿面積（㎡）

**(1) どの方式で縮尺を決めるか（判定表）**

| 地籍調査済み | 辺の基準 | 面積 | 方式 | 図面での表記 |
|---|---|---|---|---|
| どちらでも | 0本 | なし | 計算しない（`SCALE_NO_REFERENCE`） | — |
| どちらでも | 0本 | あり | 面積で決める: s = √(A/a) | 面積基準で縮尺を算出 |
| いいえ | 1本以上 | なし／あり | 辺で決める: s = Σ(lᵢLᵢ) / Σ(lᵢ²)。面積があれば、比べるだけに使う | 辺の長さ（n本）を基準に縮尺を算出 |
| はい | 1本以上 | あり | 面積で決める: s = √(A/a)。辺の長さは食い違いの表示だけに使う | 面積基準で縮尺を算出 |
| はい | 1本以上 | なし | 「いいえ」の場合と同じ | 辺の長さ（n本）を基準に縮尺を算出 |

**(2) 基準ごとの食い違い**

- 各基準から単独で出した縮尺: sᵢ = Lᵢ/lᵢ（面積の場合は √(A/a)）
- 採用した縮尺との差: (sᵢ/s − 1) × 100 %
- 一覧で表示し、差が ±3% を超える基準には印を付ける【想定】。

**(3) 縦横別の縮尺**（利用者がオンにしたときだけ）

dxᵢ・dyᵢ を、基準 i の補正後座標での横・縦の差（px）とする。

- **辺の基準が2本以上あり、面積を固定しない場合**:
  - u = sx²、v = sy² として、Lᵢ² = u·dxᵢ² + v·dyᵢ² を最小二乗法で解く（2元の正規方程式）。
  - 推定できる条件: 辺どうしの向きの差（0°〜90°の範囲に直した値）の最大が 30° 以上であること【想定】。さらに、解が u > 0 かつ v > 0 であること。
- **辺の基準が1本で、面積がある場合**:
  - k = A/a（＝sx·sy）とし、u² dx² − L² u + k² dy² = 0 を u について解く。
  - 解が2つあるときは、sx/sy が1に近いほうを採用する。判別式が負のときは推定できない。
- **地籍調査済みで、面積がある場合**:
  - k = A/a を固定し、比 r = sx/sy を求める。sx = √(k·r)、sy = √(k/r) となる。
  - Σ(Lᵢ² − k(r·dxᵢ² + dyᵢ²/r))² が最小になる r を、r ∈ [0.8, 1.25] の範囲で三分探索して求める【想定】。
  - 辺の基準が1本だけでも推定できる。
- **推定できない場合**: `ANISO_INSUFFICIENT` とし、「縦横別の縮尺は推定できません（材料不足）」と表示する。縮尺は共通縮尺を使う。
- **警告**: |sx/sy − 1| > 3% のとき、`ANISO_LARGE_RATIO` の警告を出す（計算は続ける）【想定】。

**(4) 入力チェック**

| コード | 条件 |
|---|---|
| `REF_SAME_POINT` | 基準の2点が同じ点（距離が 1px 未満） |
| `REF_NON_POSITIVE` | 長さ・面積が0以下、または数値でない |

**(5) 検証（合成データを使う）**

- 20m×30m の長方形を、s = 0.01 m/px で画像にしたデータ: 辺を1本入れると s が 0.01 ±1e-9 になる。面積 600㎡ だけを入れても同じになる。
- sx = 0.0100、sy = 0.0103 の画像で、縦の辺と横の辺を入れて推定をオンにすると、sx・sy がそれぞれ ±0.1% 以内に戻る。向きが同じ辺だけのときは `ANISO_INSUFFICIENT` になる。
- 辺を3本入れ、そのうち1本だけ長さに +5% の誤差を入れると、その基準だけに印（±3%超）が付く。

### L-05 三角形への分割と対角線の入れ替え

- **自動分割**: 耳切り法を使う。
  - 各段階で、取り除ける「耳」（内側に他の頂点を含まない凸の頂点）の候補から、できる三角形の最小内角が最も大きいものを選ぶ。
  - n 頂点から n−2 個の三角形ができる。計算量は O(n³) でよい（頂点は200個程度まで）。
- **三角形の番号**: 1から順に、作られた順番で振る。
- **対角線の入れ替え**: 対角線を共有する2つの三角形が凸の四角形をなす場合だけ、もう一方の対角線に入れ替える。凸でない場合は `FLIP_NOT_CONVEX` とし、入れ替えない。
- **頂点を変更したとき**: 頂点を追加・削除したら、自動分割をやり直す。頂点を移動しただけで、多角形として有効なままなら、分け方を保つ。分け方が無効になった場合（入れ替えで作った三角形が多角形の外に出るなど）は、自動分割をやり直し、その旨を表示する。
- **検証**:
  - 凸六角形 → 4個、L字（6頂点）→ 4個の三角形になる。
  - 三角形の面積の合計が、L-03 の面積と 1e-9 の相対誤差内で一致する。
  - 凹んだ頂点をまたぐ対角線を作らない。

### L-06 三斜求積と端数処理

各三角形について（実座標を使う）:
1. 底辺 b = 最も長い辺の長さ（m）。
2. 高さ h = 2 ×（三角形の面積）÷ b。
3. 表示する値: b_cm = round(b×100)、h_cm = round(h×100)。四捨五入で、0.5 は切り上げる。浮動小数点の誤差（例: 12.345×100 = 1234.4999…）で四捨五入が狂わないように、`Math.round(x*100 + 1e-9)` のように小さな補正値を足す。
4. 倍面積（cm²）= b_cm × h_cm。整数のまま計算する。表示は ÷10000 して小数第4位まで（㎡）。

合計と面積:
- 倍面積の合計 T（cm²）、面積の元の値 = T ÷ 2（cm²）。
- 地目による切り捨て（core/chimoku.js）:
  - 宅地・鉱泉地: floor(T/2 ÷ 100) ÷ 100 ㎡（0.01㎡未満を切り捨て）。
  - それ以外: T/2 > 100,000 cm²（10㎡）のときは floor(T/2 ÷ 10000) ㎡（整数）。10㎡以下のときは、宅地と同じく 0.01㎡未満を切り捨てる。
- 地目の一覧（不動産登記事務取扱手続準則68条の23種）:
  - 田、畑、宅地、学校用地、鉄道用地、塩田、鉱泉地、池沼、山林、牧場、原野、墓地、境内地、運河用地、水道用地、用悪水路、ため池、堤、井溝、保安林、公衆用道路、公園、雑種地
  - 条文との照合は T-006 で行う。地目が未選択のときは `CHIMOKU_REQUIRED` とする。

公簿面積との比較（面積を基準にしていない場合だけ）:
- 差 = 概算面積 − 公簿面積（㎡）
- 比率 = 差 ÷ 公簿面積 × 100（%、小数第1位まで）

座標法との確認:
- 三斜の合計（T/2）と、座標法の面積との差を内部で計算する。丸めで起こる差の範囲（Σ(b+h)×0.005㎡ 程度）を超えたら、開発用ログに出す（利用者には見せない）。

**検証**:
- 底辺 12.3456m・高さ 8.7649m の三角形 → 表示は 12.35 / 8.76、倍面積は 108.1860。
- 底辺 12.345m（ちょうど0.5cm）→ 12.35 と表示される（浮動小数点の誤差で 12.34 にならない）。
- 宅地 T/2 = 1,234,567 cm² → 123.45㎡。山林で同じ値 → 123㎡。山林 T/2 = 95,000 cm²（9.5㎡）→ 9.50㎡。
- 境界: 山林でちょうど 100,000 cm²（10㎡）→ 10.00㎡（10㎡を超えないので小数第2位まで）。100,001 cm² → 10㎡。

### L-07 図面の縮尺

- 図面上の描画範囲（用紙から余白・表・見出しの領域を除いた部分）に、実座標の外接矩形が収まる縮尺のうち、次の候補から最も大きいもの（＝最も拡大されるもの）を選ぶ: 1/100, 1/150, 1/200, 1/250, 1/300, 1/400, 1/500, 1/600, 1/1000, 1/1500, 1/2000, 1/2500, 1/5000【想定】。
- 図面には「図面縮尺 1/N」と書く。公図の推定縮尺（L-02）とは別に表示する。
- 1/5000 でも収まらない場合は、収まる倍率を計算し、「縮尺任意」と表示する。

### L-08 作成日

- 今日の日付は、`Asia/Tokyo` の今日を `yyyy-MM-dd` で返す（`todayJst(now: Date)`。now を引数で受け取れるようにして、テストできる形にする）。
- 入力欄の整形・妥当性の確認（`parseDateInput`）:
  - 8桁の数字は yyyy/MM/dd に整える。
  - 全角の数字は半角に直す。
  - 存在しない日付（例: 2026/02/30）は `DATE_INVALID` とする。
- **検証**（TZ=UTC で実行する）:
  - now = 2026-11-21T14:59:59Z → 2026-11-21
  - now = 2026-11-21T15:00:00Z → 2026-11-22
  - now = 2026-12-31T15:00:00Z → 2027-01-01
  - 2028/02/29 は有効、2026/02/29 は無効。

## エラーコードと表示文言

画面に出す文言は `src/ui/messages.js` にまとめ、エラーコードとは分けて管理する（文言の変更はA区分）。

| コード | 表示文言（初期案） | 回復方法 |
|---|---|---|
| SCALE_NO_REFERENCE | 辺の長さか面積を1つ以上入力してください | 基準の入力タブへ移る |
| POLY_SELF_INTERSECT | 外周の線が交差しています。頂点の順番か位置を直してください | 交差している辺を強調表示する |
| QUAD_DEGENERATE | 四隅の指定が正しくありません | 補正のやり直し、または補正なしで進める |
| ANISO_INSUFFICIENT | 縦横別の縮尺は推定できません（材料不足） | 共通縮尺で続ける |
| FILE_SCHEMA_UNKNOWN | このファイルは新しい版のアプリで作られています。アプリを更新してください | 現在の作業はそのまま保つ（C-04） |
